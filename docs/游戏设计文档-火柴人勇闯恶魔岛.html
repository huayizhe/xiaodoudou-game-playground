01文档定位与结论

本文是下一版游戏的目标设计评审稿，不是对当前线上功能的宣称。当前 stickman.html 仍是 5 关版本；本文经确认后才进入开发，开发后的实际数值还需通过试玩校准。

本轮定案：100 关连续闯关；清关后先结算，再进入三选一强化；强化界面不倒计时，玩家不选就一直安全暂停；选完后经过 2 秒过渡自动进入下一关。关卡选择保留，但独立于主闯关存档。

设计要解决的四个问题

  1. 推进断档：取消每关手动点击「下一关」，但不取消玩家主动休息的权利。
  2. 百关疲劳：用章节、敌人组合、场地机制和 BOSS 变化递进，而不是只增加血量。
  3. 长线无力：血量、怒气、技能冷却和强化在闯关模式内连续继承，失败只重打当前关。
  4. 双端失衡：PC 与移动端共享战斗数值和关卡内容，仅调整输入与视觉性能，不暗改任何一端难度。

03体验支柱与边界

不停冲锋，也能随时停下自动推进消灭重复点击；强化界面与暂停菜单提供绝对安全的休息点。
四招各有用途Z 解围、X 位移续航、C 聚怪控制、V 收割；强化加深用途而不是制造一个万能键。
难度来自可读的组合所有重击有预警，危险不只靠颜色表达；不靠无限提速和血量膨胀制造伪难度。
双端同等完整同一关卡、敌人、强化、评分与存档能力；移动端不是简化版，PC 也不是触控版的附属。

本轮明确不做

联机付费数值金币商店装备背包随机关卡地图强制每日签到隐藏动态难度

无尽模式与高难周目可以作为 100 关完成后的扩展，但不阻塞首轮百关开发。移动端以横屏为完整战斗形态；竖屏不阻断菜单和存档操作，并明确引导旋转。

04核心循环与自动推进

秒级循环

走位聚怪 → 自动普攻 → 四技能解围 / 控制 / 收割 → 管理血量与怒气。

关卡循环

清波 → BOSS 或关底 → 轻结算 → 三选一强化 → 自动进入下一关。

章节循环

学习新机制 → 组合考验 → 小 BOSS → 机制变体 → 大 BOSS → 新章节。

长期循环

推进解锁 → 刷新单关评级 → 完成 100 关 → 再考虑无尽或高难周目。

一关结束后的准确状态顺序

  1. 胜利收尾：立即停止敌方伤害与新出怪，清理残余弹体；不再出现“BOSS 已死仍被小怪打死”。
  2. 轻结算：展示关卡、评级、用时和剩余血量，停留约 1.2 秒；不覆盖整屏长报告。
  3. 关卡恢复：普通关 +6% 最大生命，小 BOSS +20%，大 BOSS +35%；显示血条绿光与实际数值。
  4. 强化暂停：弹出三选一，战斗计时、敌方、冷却和强化界面均无倒计时；这是无限休息点。
  5. 自动衔接：选定后关闭面板，显示下一章 / 下一关名称，2 秒后可移动但不受伤害，随后出怪。
不选就不推进：强化界面没有“超时自动选择”。玩家可以停在这里休息；切后台、失焦或锁屏也保持暂停，回来后仍停留在同一选择。

失败与主动退出

死亡后提供「重试本关」「保存并返回标题」。重试读取本关入口快照，不丢失已有关卡与强化。战斗中退出只保证从本关入口继续，不承诺恢复到某一帧或某一波，界面需明确写出这一点。

保留的基础战斗数值

第一关仍以当前角色与技能为基准：100 生命、255 移速、0.30 秒普攻间隔、Z 5 秒、X 8 秒、C 9 秒、V 需 100 怒气。后续强化在此基础上叠加，具体叠层上限见下一节。

百关版必须同步修正的旧问题

  • 盾卫受到技能命中或强击退后增加 1.5 秒破防窗口，避免自动锁敌与绕后互相打架。
  • 巫妖每场最多召唤 8 只小鬼；召唤时有 0.6 秒可识别硬直，不能无限拖长关卡。
  • 清波 +3% 回血增加可见反馈；大招期间击杀回怒保留减半原则，新增强化不得绕过该限制。
  • 波次结束、BOSS 死亡和关卡胜利统一走安全结算，先停伤害再播放演出。

06局内强化系统

每关胜利后三选一，100 关完整流程最多获得 99 次强化。强化只服务于本轮闯关，不引入额外货币。第一章优先出现易懂的基础强化，第二章起加入进阶联动，大 BOSS 后必出一项核心强化。

强化池与叠层约束

流派代表强化上限 / 互斥改变的决策
普攻 · 连斩第三段射程 +12%；三段命中后下一击伤害 +20%；高连击时怒气获取小幅提高射程最多 3 层；增伤最多 3 层主动维持三段节奏，而不是只按技能
Z · 旋风范围 +12%；击杀 3 只减 1 秒冷却；加速期间减伤 15%范围最多 3 层；减冷却每次施放最多触发一次冲进怪群解围后安全撤出
X · 跃斩落点留 3 秒裂隙；回血 +4% 最大生命；空中落地后重置少量闪避冷却额外回血最多 3 层；裂隙伤害不可无限叠加选择进攻落点或保命落点
C · 裂空投抓取数 +1；落点二次爆炸；眩晕结束后目标受伤 +10%抓取最多 8 只；易伤最多 3 层围绕聚怪和集火高威胁目标构筑
V · 无影最大斩击目标 +1；收尾范围 +15%；对 BOSS 的最后一击额外破防目标最多 +4；大招期间命中仍不回怒决定清群怪还是留给 BOSS 爆发
闪避 · 生存完美闪避回 6 怒；最大生命 +10；每关首次致命伤保留 1 血保命每个大章节最多触发一次鼓励读预警，提供有限容错而非永久无敌

选项生成规则

  1. 三项至少来自两个不同流派，已满层或互斥强化不再出现。
  2. 第 1–3 关不出现复杂联动；第 5 关后开放进阶强化；每章大 BOSS 后提供核心强化。
  3. 不根据血量偷偷操纵选项品质；低血时可以提高生存项出现率，但必须在设计口径中公开，不改变稀有度。
  4. 所有项目满层时，后备选项固定为「最大生命 +5」或「恢复 20% 生命」，不出现空面板。
  5. 暂不提供刷新、锁定、出售和强化货币，避免 99 次选择变成菜单负担。

选择界面双端等价操作

PC 支持鼠标点击、方向键切换、数字键 1/2/3 直选、Enter 确认；移动端直接点按大卡片。选择后立即显示已获得的简短反馈，再进入 2 秒过渡。面板打开时清空摇杆与键盘残留输入，禁止穿透触发技能。

波次配置使用威胁预算

不单纯写死怪物总数。每类敌人有威胁成本，小鬼 1、炸弹鬼 1.5、眼球怪 2、胖魔 / 盾卫 3、巫妖 4、疾风魔 3、虚空魔 4；每波用预算选择固定模板，再只随机入场顺序与合法出怪点。

首轮原型波次预算从 6 + 0.08×(关−1) + 1.2×(波序−1) 起步。该公式只用于第一版生成数据，最终以通关时间、受击次数和失败率调整，不能把公式当成已经验证的平衡结果。

公平出怪与节奏

  • 出怪点离玩家至少 200 px，不在当前移动方向贴身生成，不在触控按钮遮挡区生成。
  • 入场预警与不可选中时间保持一致；结束后才允许造成伤害。
  • 普通关波间 1.5–2 秒；清波回血有文本与血条反馈。
  • 同屏逻辑敌人上限先以 32 验证，双端一致；达到上限时延迟后续出怪，不偷偷减少总敌人或更换 AI。
  • 战斗目标是保持可读密度，而非把百关后期变成满屏弹幕。

11大小 BOSS 体系

小 BOSS：一个核心考点

小 BOSS 采用现有敌人放大与一招新变化，1–2 阶段即可。重点检验本章前半段技能，例如岩甲胖魔在冲撞撞墙后破甲，祭坛巫妖在治疗读条时暴露弱点。目标击杀时间 45–75 秒，不靠超大血量延长。

大 BOSS：章节综合考试

大 BOSS 使用 2–3 阶段，每阶段只增加一个主要变化。阶段切换时清除无法避免的旧弹体、暂停伤害约 1 秒并展示新招式预警。BOSS 被击败后立即停止全场伤害，再播放收尾演出。

失败辅助

同一关连续失败 3 次后，明确提供可选辅助：「本关初始生命 +20%」或「敌方伤害 −15%」。玩家主动选择才生效，辅助成绩正常解锁下一关但标注使用辅助；绝不暗中改变难度。

移动端布局底线

  • 横屏是完整体验基准；覆盖 568×320、667×375、844×390、932×430 等视口，并叠加左右与底部安全区。
  • 常用触控目标不小于 44 CSS px；主技能和摇杆保留现有较大尺寸。技能、闪避、暂停和 HUD 不互相遮挡。
  • 支持双指同时移动与放技能；pointercancel、失焦、旋转和打开面板时归零摇杆，防止持续移动或误触。
  • 提供按钮尺寸 90% / 100% / 115% 与左右布局镜像选项；只改布局，不改触发范围之外的战斗数值。
  • 全屏与锁横屏只能由用户手势尝试；浏览器拒绝时不阻断游戏。强化卡片在矮屏采用紧凑横排，不允许关键按钮离屏。

PC 操作底线

不要求鼠标瞄准；全部战斗可以只用键盘完成。菜单和强化有可见焦点，Enter 不会误触发已经消失的下一关按钮。窗口失焦自动暂停，回来后由玩家主动继续。

15存档、续玩与选关

闯关快照

每次进入新关且强化选择完成后写入快照：当前关号、生命、最大生命、怒气、强化与叠层、辅助状态、累计统计。单关进行中的敌人位置、弹体和波次不保存；退出或浏览器异常关闭后从最近一关入口恢复。

数据保存时机读取行为
最高解锁关每关胜利上限 100，决定选关可见范围
闯关快照每关入口、强化完成后继续闯关恢复；重试本关恢复同一快照
单关最佳练习模式胜利与闯关成绩分开，取更高评级和更短时间
设置声音、触控尺寸、镜像、减弱震动等改变时跨会话保留，不影响战斗公平性

存档容错与旧版迁移

新版使用独立版本字段并做字段级校验；损坏或写入失败时保留可玩的新会话并给出非阻断提示。读取现有 stickman_demon_isle_v1 时只迁移最高解锁进度；由于关卡结构、时长和评价已经重构，旧星级与最佳时间不直接冒充新版成绩，旧键也不删除。

为什么保留选关

选关用于重玩、补评级、BOSS 练习和短时游玩。进入练习关时使用该章预设的标准强化模板与满血状态，不读取玩家过强或过弱的闯关构筑，也不覆盖闯关快照。这样第 50 关既不会因零基础而无法玩，也不会污染主流程成长。

16表现、性能与无障碍

表现反馈

  • 保留红绫与技能残影；普通击杀不震屏，重击震屏短促且可减弱。
  • 危险区域同时有轮廓、形状 / 方向和动画前摇，不只靠红绿颜色区分。
  • 强化获得、破防、清波恢复和 BOSS 阶段变化各有独立反馈，但同屏横幅最多一条。
  • 技能伤害数字和粒子设上限；降低视觉档位时保留预警圈、命中判定与输入反馈。

持续性能治理

项目目标口径
帧率参考设备以 60 fps 为目标；高负载允许稳定 30 fps，不能在 BOSS 阶段突然长时间卡顿

逻辑统一时间步长来源；暂停、切后台和强化界面不会积累一个超大 dt

可访问性与舒适度

设置提供减弱震屏、减弱全屏闪烁、音量 / 静音、触控尺寸与镜像。系统要求减少动态效果时默认降低非必要演出，但不移除战斗预警。失败后辅助是显式选项，PC 与移动端均可使用。

18开发分期与确认项

阶段四 · 双端打磨实机调触控、反馈、性能、辅助与存档容错；同步更新 README 和文档为实际实现。无尽 / 周目不纳入首轮完工条件。
